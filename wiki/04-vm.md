# 04 - L4 Execution Layer — `qvm/`

> QVM is Quantaureum's **quantum-native virtual machine**: it neither depends on
> the EVM nor has its own QASM assembly language for compiling smart contracts.
> This section clarifies the execution core, stack semantics, JIT discipline, and AA hooks.

## 4.1 Positioning

- Execution entry points: `qvm/executor.go` (`Executor`), `qvm/qvm.go` (VM state machine).
- Contract bytecode format: **QASM** (Quantum Assembly), different from EVM bytecode.
- Compilation: `cmd/qasm` (QASM assembler, see [10-entrypoints.md](./10-entrypoints.md)).
- Interop with the EVM: `evm_translate.go` translates valid EVM contracts into QVM-executable
  instructions (only a syntax-subset compatibility, not full EVM).

## 4.3 Opcode Stack Order (Different from EVM!)

> This is one of the easiest pits to fall into on Quantaureum. QVM's operand order is
> the reverse of the EVM's.

| Opcode | QVM Semantics |
|--------|---------|
| `LT` | Pop `a`(top), `b`(second), return `a < b ? 1 : 0` |
| `SUB` | Pop `a`(top), `b`(second), return `a - b` |
| `DIV` | Pop `a`(top), `b`(second), return `a / b` |
| `MSTORE` | Pop `offset`(top), `value`(second), write `memory[offset] = value` |
| `CALLDATALOAD` | Read 32 bytes from `calldata[offset]`; result is left-aligned (selector in the high bits) |

## 4.4 QASM Function Dispatcher (Must Add SHR 224)

`CALLDATALOAD(0)` places the 4-byte selector in the **high bits**, while `PUSH4`
places it in the **low bits**. Therefore the standard dispatcher pattern must be:

```
CALLDATALOAD(0)
PUSH1 0xe0
SHR
PUSH4 0xffffffff
AND
PUSH4 <selector>
EQ
```

## 4.5 QASM Function Body Entry Must POP the Selector

The dispatcher uses `DUP1` to copy the selector for the EQ comparison; after jumping
to a function body the selector is still on the stack. **Every function body must add
`POP` after its `JUMPDEST`**.

## 4.6 QASM PUSH Byte Count Must Match the Opcode

The number in `PUSH1-PUSH32` must strictly match the number of following bytes
 (PUSH1=1 byte,…,PUSH8=8 bytes). A mismatch misaligns the bytecode stream and the
behavior becomes unpredictable.

## 4.7 QASM Function Selectors Are Custom, Not keccak256

QASM contract function selectors are **manually defined** in the source
(e.g., `0x3fb5c1c1`), **not** `keccak256("release()")[:4]`. Check the QASM source
definitions before calling.

## 4.8 Must Check the Return Value After a QVM CALL

A failed CALL returns 0 but **SSTORE does not automatically roll back**. You must use:

```
CALL → DUP1 → ISZERO → JUMPI @failed → POP
```

On failure, `REVERT` rolls back all state changes. This is the root cause behind the
"QVM reentrancy-check lesson" in [15-lessons.md](./15-lessons.md).

## 4.9 JIT Compiler Is Disabled by Default

- `jitEnabled: false` in `qvm/executor.go`.
- `compileOp()` is incomplete; **do not enable it until it is fully implemented**.
- When faster contract execution is needed, prefer optimizing the critical paths in
  `operations.go` rather than enabling JIT.

## 4.10 Reentrancy Protection

- `call.go` maintains `callDepth`.
- Rule: `callDepth >= 1 && IsAddressActive(addr) && targetHasCode(addr)` may be blocked.
- **Key lesson**: `targetHasCode` distinguishes EOA (no code; transfers should not be
  blocked) from contracts. Relying only on "internal bookkeeping was updated" is not
  enough to prove a transfer succeeded; you must verify the actual balance change
  (see [15-lessons.md](./15-lessons.md)).

## 4.11 Gas and AA

- Each transaction is billed at `gasPrice × gasUsed`, which enters the validator/staking-pool rewards.
- `txpool/executor.go` and `qvm/paymaster.go` hook into ERC-4337:
  - `UserOperation` submission → `entrypoint` verifies signature + paymaster validation
  - On success, the `UserOperation` is bundled into a node transaction and executed.

## 4.12 Test Discipline

- Executor unit tests must cover: normal/boundary/error paths for every opcode.
- The bytecode in contract deployment tests (e.g., `qvm/vesting_test.go`) is the
  **single authoritative source for that contract** (see [15-lessons.md § R40.B](./15-lessons.md#152-r40b---bytecode-single-source-of-truth))
  — all `.hex` build artifacts must be rewritten against it and must not trust `/tmp/*.hex` directly.
